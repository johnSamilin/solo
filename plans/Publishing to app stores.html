Publishing Solo on Google Play, RuStore, F-Droid, and Snap Store

Solo consists of two clients:

  • Android: native-clients/android, Kotlin + WebView with the web app;
  • Linux desktop: native-clients/electron, Electron.

The Android builds are already split into the googlePlay and ruStore flavors. Google Play requires an Android App Bundle (.aab); RuStore requires a signed APK (.apk). F-Droid does not accept uploaded binaries: it builds the FOSS app from source code. To get Solo into the Ubuntu app store, the Electron client must be published as a snap in the Snap Store.

1. General Preparation

  1. Choose the owner, package name, and permanent identifiers:

    • Android package: currently com.solo.app;
    • Snap name: for example solo-notes, if solo is already taken;
    • GitHub repository: currently https://github.com/johnSamilin/solo.

    The applicationId cannot be changed after the first publication without shipping a brand-new app. First verify that com.solo.app is available in Google Play Console and RuStore Console.

  2. Maintain a single version across all clients. Currently Android and Electron use 3.6.0, and the Android versionCode is 3. Before each release, update:

    • version in package.json;
    • version in native-clients/electron/package.json;
    • versionName and the next higher versionCode in native-clients/android/app/build.gradle.kts;
    • CHANGELOG.md.

  3. Add an explicit open-source license to the repository root, for example a LICENSE file with the GPL-3.0-or-later text or another F-Droid-compatible license. The README currently says NO LICENSE; this blocks publication on F-Droid. A license should be chosen only if the author is genuinely willing to release the source code under its terms.

  4. Prepare the public-facing materials:

    • a privacy policy at a stable HTTPS URL;
    • a support address;
    • a 512 x 512 px PNG icon;
    • at least 2 honest screenshots of the Android UI;
    • a description, category, and content rating;
    • a complete list of collected and transmitted data.

    The description may state that Solo stores notes locally as HTML. Do not claim "no cloud" or "no data transmission" until this has been confirmed by auditing all dependencies and network calls.

  5. Run the basic checks for the web and desktop clients from the repository root:

    npm ci
npm run lint
npm test
npm run build
npm --prefix native-clients/electron ci
npm --prefix native-clients/electron run lint
npm --prefix native-clients/electron run typecheck

2. Prepare the Android Release

Review Permissions

native-clients/android/app/src/main/AndroidManifest.xml contains:

  • MANAGE_EXTERNAL_STORAGE;
  • READ_MEDIA_IMAGES;
  • network access.

MANAGE_EXTERNAL_STORAGE is a restricted Google Play permission. It is allowed only if full storage access is the app's core functionality. For Solo, the preferable approach is to let the user pick a directory via the Storage Access Framework and persist long-term access to the chosen directory, without accessing the whole device. If the permission is kept:

  1. Prepare a video showing that the key feature cannot work without it.
  2. Complete the All files access declaration in Google Play Console.
  3. Clearly explain its necessity to RuStore.

Google Play also checks targetSdk. The project currently targets API 34. Right before submission, verify the current requirement in Play Console and update compileSdk/targetSdk in native-clients/android/app/build.gradle.kts if required.

Create the Signing Key

A single keystore is used for all future Android updates and for RuStore. Keep it out of Git and create a secure backup.

keytool -genkeypair \
  -keystore "$HOME/.android/solo-release.jks" \
  -alias solo \
  -keyalg RSA \
  -keysize 4096 \
  -validity 10000

Create native-clients/android/keystore.properties and add it to .gitignore:

storeFile=/Users/USER/.android/solo-release.jks
storePassword=CHANGE_ME
keyAlias=solo
keyPassword=CHANGE_ME

Then wire the file into native-clients/android/app/build.gradle.kts:

import java.util.Properties

val keystoreProperties = Properties().apply {
    val file = rootProject.file("keystore.properties")
    require(file.exists()) { "Release signing requires keystore.properties" }
    file.inputStream().use(::load)
}

android {
    signingConfigs {
        create("release") {
            storeFile = file(keystoreProperties["storeFile"] as String)
            storePassword = keystoreProperties["storePassword"] as String
            keyAlias = keystoreProperties["keyAlias"] as String
            keyPassword = keystoreProperties["keyPassword"] as String
        }
    }
    buildTypes {
        release {
            signingConfig = signingConfigs.getByName("release")
        }
    }
}

Never commit real passwords or the .jks file to the repository. In CI, store them only in protected/secret variables.

Build and Verify

The web assets must be built before the Android Gradle build. Run from the repository root:

npm ci
npm run build:android
./native-clients/android/gradlew -p native-clients/android clean test lint
./native-clients/android/gradlew -p native-clients/android bundleGooglePlayRelease assembleRuStoreRelease

Release artifacts:

ls -lh native-clients/android/app/build/outputs/bundle/googlePlayRelease/app-googlePlay-release.aab
ls -lh native-clients/android/app/build/outputs/apk/ruStore/release/app-ruStore-release.apk
apksigner verify --verbose --print-certs \
  native-clients/android/app/build/outputs/apk/ruStore/release/app-ruStore-release.apk

Test the RuStore APK on a clean device:

adb uninstall com.solo.app
adb install native-clients/android/app/build/outputs/apk/ruStore/release/app-ruStore-release.apk

Verify directory picking, creating/editing an HTML note, images, search, app restart, and updating over the previous version. Test the AAB via Google Play Internal testing.

3. Publish on Google Play

  1. Register a Google Play Developer account, pay the registration fee, and complete the requested verification.

  2. In Google Play Console, create the app with package name com.solo.app.

  3. Fill in the Store listing: title, descriptions, icon, screenshots, a 1024 x 500 px feature graphic, contact details, and the privacy policy.

  4. In App content, complete Privacy policy, Ads, App access, Content rating, Target audience, and Data safety.

  5. If MANAGE_EXTERNAL_STORAGE is kept, complete the All files access declaration with a justification and video.

  6. Enable Play App Signing on the first release. Google will manage the app-signing key, while the created keystore remains the upload key.

  7. Create an Internal testing release and upload:

    native-clients/android/app/build/outputs/bundle/googlePlayRelease/app-googlePlay-release.aab

  8. Have testers install the build from the Play Store. For new personal accounts, Google may require closed testing before production: follow the Console's requirement.

  9. After testing, create a Production release, add release notes, and submit it for review.

4. Publish on RuStore

  1. Create and verify an account in RuStore Console as an individual, self-employed person, sole proprietor (IP), or legal entity.

  2. Create the app with the same package name com.solo.app.

  3. Fill in the store listing: description, category, contacts, privacy policy, content rating, icon, and screenshots.

  4. Create a release and upload:

    native-clients/android/app/build/outputs/apk/ruStore/release/app-ruStore-release.apk

  5. Provide details about data, monetization, ads, and special permissions. Explain the all-files access if it has not been removed.

  6. Submit for moderation; after approval, publish the release and install it from RuStore on a real device.

5. Prepare the F-Droid Release

F-Droid publishes only free and open-source software. You cannot upload app-ruStore-release.apk or app-googlePlay-release.aab to it. The process is: prepare a reproducible build, add metadata to the fdroid/fdroiddata repository, and wait for their infrastructure to build and sign the APK.

Requirements

  • A FOSS license compatible with the source code and dependencies is present at the repository root.
  • The Android source code, web assets, and all required dependencies are publicly available under an immutable git tag.
  • The build does not download proprietary dependencies, trackers, or closed-source SDKs.
  • No mandatory anti-features: ads, tracking, a required external account, or non-free network services without a free alternative.
  • The app builds without secrets, local paths, or pre-copied untracked assets.

The current project needs work to reach this state: copy-web-assets.sh and the Gradle build must either build the web client themselves or obtain it from source in a deterministic way. The F-Droid build server cannot use the locally created app/src/main/assets folder, because it is excluded from Git.

Add Fastlane Metadata

Create the directory native-clients/android/fastlane/metadata/android/en-US/ with at least these files:

title.txt
short_description.txt
full_description.txt

Place the PNG screenshots in:

native-clients/android/fastlane/metadata/android/en-US/images/phoneScreenshots/

Example commands:

mkdir -p native-clients/android/fastlane/metadata/android/en-US/images/phoneScreenshots
touch native-clients/android/fastlane/metadata/android/en-US/title.txt
touch native-clients/android/fastlane/metadata/android/en-US/short_description.txt
touch native-clients/android/fastlane/metadata/android/en-US/full_description.txt

Add the Russian locale the same way under android/ru-RU/.

Create the F-Droid Variant

Create an fdroid flavor without services or dependencies prohibited by F-Droid policy. Its application ID must be the same as the main FOSS version, for example com.solo.app; the flavor must not add any mandatory proprietary SDKs.

Once Gradle can prepare the assets deterministically, verify the build locally:

npm ci
npm run build:android
./native-clients/android/gradlew -p native-clients/android assembleFdroidRelease

Create a signed git tag of the sources:

git tag -s v3.6.0 -m "Solo 3.6.0"
git push origin v3.6.0

Prepare the metadata/com.solo.app.yml file in a fork of the fdroid/fdroiddata repository. It records the source URL, tag/commit, Android subdirectory, Gradle flavor, version numbers, license, build description, and anti-features if any. Use the template and validator from the F-Droid documentation, then open a Merge Request in fdroid/fdroiddata.

Do not use the Google Play key for F-Droid: F-Droid signs the APK with its own signing key. Because of the different signatures, users cannot update an APK installed from Google Play/RuStore via F-Droid, or vice versa. This is a normal limitation and should be noted on the downloads page.

6. Publish the Electron Client on Snap Store

Electron Forge currently produces a DEB, but there is no snapcraft.yaml. A separate snap recipe is needed. A convenient place for it is the repository root: that way the build has access to both the web project and native-clients/electron.

Set Up Snapcraft

On Ubuntu, install the tools and log in:

sudo snap install snapcraft --classic
snapcraft login

Register the package name in advance so another developer does not take it:

snapcraft register solo-notes

Create snap/snapcraft.yaml at the project root. This is a working starting configuration for x86_64; before production, replace the owner, links, and version:

name: solo-notes
base: core22
version: "3.6.0"
summary: Local-first HTML notes
description: |
  Solo is a private local-first note-taking application.
  Notes are stored as HTML files chosen by the user.
grade: devel
confinement: strict
license: GPL-3.0-or-later
website: https://github.com/johnSamilin/solo
source-code: https://github.com/johnSamilin/solo
issues: https://github.com/johnSamilin/solo/issues
contact: https://t.me/WatasheeBaka
architectures:
  - build-on: [amd64]
    build-for: [amd64]

apps:
  solo-notes:
    command: opt/solo/solo
    desktop: usr/share/applications/solo-notes.desktop
    plugs:
      - desktop
      - desktop-legacy
      - wayland
      - x11
      - opengl
      - audio-playback
      - home

parts:
  solo:
    plugin: nil
    source: .
    build-packages:
      - nodejs
      - npm
      - python3
      - make
      - g++
    override-build: |
      npm ci
      npm --prefix native-clients/electron ci
      npm --prefix native-clients/electron run package
      mkdir -p "$CRAFT_PART_INSTALL/opt/solo"
      cp -a native-clients/electron/out/Solo-linux-x64/. "$CRAFT_PART_INSTALL/opt/solo/"
      mkdir -p "$CRAFT_PART_INSTALL/usr/share/applications"
      cp snap/gui/solo-notes.desktop "$CRAFT_PART_INSTALL/usr/share/applications/"

native-clients/electron/out/Solo-linux-x64 is the expected Electron Forge output path for the current app name. If the package command produces a different path, replace it in the cp command and pin that in the recipe.

Add snap/gui/solo-notes.desktop:

[Desktop Entry]
Name=Solo
Comment=Local-first HTML notes
Exec=solo-notes
Icon=solo-notes
Terminal=false
Type=Application
Categories=Office;Utility;
StartupWMClass=Solo

Copy the PNG/SVG icon to snap/gui/solo-notes.png. The Icon= identifier in the desktop file must match the icon file name without the extension. Add the removable-media plug only if the app truly needs USB drives or SD cards: it requires manual connection by the user after installation.

Verify that the desktop client can be built on Ubuntu x86_64:

npm ci
npm --prefix native-clients/electron ci
npm --prefix native-clients/electron run make:linux

After adding the recipe, build and test the snap:

snapcraft
sudo snap install --dangerous solo-notes_3.6.0_amd64.snap
solo-notes
snapcraft lint solo-notes_3.6.0_amd64.snap

--dangerous is only needed for locally installing an unsigned snap. Verify launch, opening and saving notes, home-directory access, file dialogs, the icon, and the app appearing in the Ubuntu application menu.

Submit to Snap Store

  1. Sign in to the Snapcraft Dashboard with the same account that registered the name.

  2. Check the store listing: description, category, license, screenshots, icon, website, and source-code link.

  3. Upload a test build to the edge channel:

    snapcraft upload --release=edge solo-notes_3.6.0_amd64.snap

  4. Install it on a separate Ubuntu machine:

    sudo snap install solo-notes --edge

  5. After testing, promote the same revision to candidate, then to stable, via the Dashboard or CLI:

    snapcraft release solo-notes <revision> candidate
snapcraft release solo-notes <revision> stable

    <revision> is the revision number Snapcraft returns after upload. Once published to stable, the app becomes available through Ubuntu App Center/Snap Store.

7. Releasing Updates

  1. Update all version numbers and CHANGELOG.md.

  2. Build and verify the Android artifacts:

    npm ci
npm run build:android
./native-clients/android/gradlew -p native-clients/android clean test lint \
  bundleGooglePlayRelease assembleRuStoreRelease

  3. Upload the new AAB to Google Play and the new APK to RuStore. The versionCode must be greater than the previous one.

  4. For F-Droid, create a new signed git tag and update the build block in the fdroiddata Merge Request.

  5. For Snap, update the version, build, and publish:

    snapcraft
snapcraft upload --release=edge solo-notes_<version>_amd64.snap

  6. Always test updates first via Google Play internal/closed testing and Snap edge/candidate, then promote them to production/stable.

Checklist

  • [ ] An agreed FOSS license and a LICENSE file are in place.
  • [ ] The privacy policy and contact details are published.
  • [ ] Privacy and network-activity claims have been verified.
  • [ ] The need for MANAGE_EXTERNAL_STORAGE has been reviewed or removed.
  • [ ] targetSdk meets the current Google Play requirement.
  • [ ] The Android keystore is stored outside Git and backed up.
  • [ ] The Google Play AAB and RuStore APK are built and signed.
  • [ ] Updating and clean-installing the Android app have been tested.
  • [ ] For F-Droid, the build is reproducible from a public tag without local assets or secrets.
  • [ ] For F-Droid, Fastlane metadata and a Merge Request in fdroiddata have been added.
  • [ ] snap/snapcraft.yaml, the desktop file, and the icon have been added.
  • [ ] The snap has been tested locally and published to edge before stable.
