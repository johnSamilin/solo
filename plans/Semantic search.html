Plan - Go CLI Semantic Search Tool (solo-instruments-semantic-search)

Task

Create a standalone Go program in solo/instruments that:

  • compiles as a CLI tool for Ubuntu;
  • takes a rootFolder and a search query (text + optional tags) and performs semantic search among the files in that folder using a local (offline) neural network model;
  • takes a rootFolder and a command to rebuild the index;
  • searches among .html note files; next to each html there is a .json file with the same name containing metadata (tags, paragraphTags, etc. — important for search).

This task is the Go/CLI counterpart of the existing Electron plan semantic-search.md, but as a self-contained portable binary without Node/Electron.

Refined decisions

  1. Embedding model: ONNX Runtime via onnxruntime-go (github.com/yalue/onnxruntime_go), the all-MiniLM-L6-v2 model in ONNX format (same model as in the Electron plan, so that embeddings are comparable). Implemented and verified end-to-end with ONNX Runtime 1.26.0 and the model/tokenizer from Xenova/all-MiniLM-L6-v2 (HuggingFace).
  2. CLI interface: a single solo-search binary with subcommands:
    • solo-search index --root <dir> [--model-dir <dir>] — build/rebuild the index;
    • solo-search query --root <dir> [--query "<text>"] [--tags "<boolean expression>"] [--model-dir <dir>] — search. At least one of the --query/--tags parameters must be specified (both together are also allowed); if neither is specified — error. The result is printed to stdout as JSON.
  3. Index storage: a SQLite file <root>/.solo-index/index.db, accessed without cgo via modernc.org/sqlite (the only heavy C dependency is ONNX Runtime itself).
  4. Model/tokenizer: files model.onnx, tokenizer.json, etc. are shipped next to the binary in a models/ folder (placed into the repository/distribution manually); the path can be overridden with the --model-dir flag or an environment variable (e.g. SOLO_SEARCH_MODEL_DIR).
  5. Document chunking: by paragraphs. Each HTML element p/h1-h6/li with a data-tags attribute (see ParagraphTags.ts and extractParagraphTags()) becomes a separate chunk with its own paragraphTags. Search returns the specific matching paragraphs, not the whole file.
  6. Interaction of --query and --tags: at least one of the parameters is required.
    • Both specified (--query and --tags): --tags acts as a soft relevance boost (not a hard AND filter, does not exclude results without tags). The --tags value is a boolean expression over the tag set of a chunk/file, e.g. foo AND (bar OR baz). Final relevance = semantic similarity + boost for a tag-expression match.
    • Only --tags specified (no --query): no semantic ranking — --tags acts as a hard filter, selecting only the subset of chunks/files that exactly satisfy the tag expression (the result is sorted, e.g. by date or by path, without a score).
    • Only --query specified (no --tags): pure semantic search without tag consideration.
    • If neither parameter is specified — the CLI returns a validation error.

Metadata format

Mirrors the TS type FileMetadata:

{
  "id": "string",
  "tags": ["string"],
  "createdAt": "ISO-date",
  "theme": "string (optional)",
  "paragraphTags": ["string"]
}

For each note.html there is a note.json next to it — the same way this is already implemented in the Electron handlers (main.ts:709, main.ts:765).

Architecture

flowchart TD
    CLI[solo-search CLI] --> Index[index command]
    CLI --> Query[query command]

    Index --> Walker[Traverse rootFolder]
    Walker --> HTMLParse[Parse HTML into paragraphs]
    Walker --> MetaRead[Read sidecar JSON metadata]
    HTMLParse --> Embed[ONNX embedding of chunks]
    MetaRead --> Embed
    Embed --> Store[SQLite index.db in rootFolder slash .solo-index]

    Query --> QEmbed[ONNX embedding of the query]
    Query --> TagExpr[Parse boolean tag expression]
    QEmbed --> Search[Cosine similarity over paragraphs]
    TagExpr --> Search
    Store --> Search
    Search --> JSONOut[JSON result to stdout]

Module structure (plan)

solo/instruments/semantic-search/
├── go.mod
├── README.md
├── Makefile                      # build for linux/amd64
├── models/                       # model + tokenizer (manually placed files)
├── cmd/solo-search/main.go       # index/query subcommand parsing
└── internal/
    ├── embedding/                # ONNX model loading, tokenization, mean-pooling
    ├── htmlparse/                # paragraph extraction + data-tags
    ├── metadata/                 # reading/structures for sidecar JSON
    ├── store/                    # SQLite schema and index access
    ├── indexer/                  # rootFolder traversal, incremental update
    └── query/
        ├── tagexpr/               # boolean tag expression parser
        └── search/                # cosine similarity + boost + top-N

Step-by-step implementation plan

  1. Initialize the Go module in solo/instruments/semantic-search (go.mod, basic directory structure cmd/internal/models).
  2. Implement the CLI scaffolding in cmd/solo-search/main.go: parsing of the index and query subcommands and the common flags --root, --model-dir (and/or the environment variable SOLO_SEARCH_MODEL_DIR).
  3. Implement loading of the ONNX model (all-MiniLM-L6-v2) and tokenizer via onnxruntime-go: internal/embedding (model.go, tokenizer.go, embedder.go) with mean-pooling and vector normalization.
  4. Implement the note HTML file parser in internal/htmlparse: splitting into paragraphs (p, h1-h6, li), extracting data-tags as paragraphTags for each paragraph.
  5. Implement reading of sidecar JSON metadata (internal/metadata): a FileMetadata struct (id, tags, createdAt, theme, paragraphTags) mirroring the TS type FileMetadata.
  6. Design and implement the SQLite index storage (internal/store): files/paragraphs/meta schema, DB initialization at <root>/.solo-index/index.db, migrations when the model changes.
  7. Implement the indexer (internal/indexer): traverse rootFolder, hash files (html+json) for incremental updates, embed new/changed paragraphs, delete records for removed files.
  8. Implement the boolean tag expression parser (internal/query/tagexpr): grammar with AND/OR/NOT and parentheses, e.g. foo AND (bar OR baz), evaluating a match against a paragraph's tag set.
  9. Implement the query subcommand logic in internal/query/search, supporting three modes:
    • --query + --tags: embed the query, cosine similarity over all paragraphs, soft relevance boost for a tag-expression match, top-N sorting;
    • --tags only: hard filtering of paragraphs/files by the tag expression without semantic ranking;
    • --query only: pure semantic search without tag consideration. Validation: if neither --query nor --tags is provided — return an error.
  10. Implement JSON result output to stdout (result structures: filePath, paragraphIndex, text, tags, score, semanticScore, tagBoost, note metadata).
  11. Prepare the Ubuntu build (Makefile/cross-compile script GOOS=linux GOARCH=amd64, CGO_ENABLED=1), document the dependency on libonnxruntime.so and its placement.
  12. Add a README with instructions for obtaining the model/tokenizer (models/), examples of the index and query commands, and a description of the JSON output format.
  13. Write unit tests: tag expression parser, paragraph extraction from HTML, cosine similarity, index/query round-trip on test files.

Possible enhancements (discussed, but deferred/not included in the first iteration)

  • A status subcommand to check the index state (number of files/chunks, last indexing date, model version).
  • Indexing PDF files alongside HTML (would require text extraction from PDF, e.g. via pdfcpu/ledongthuc/pdf, and defining an analog of paragraphTags for PDF content).

These items can be added as separate steps to the todo list before implementation starts, if a decision is made to include them in scope.
